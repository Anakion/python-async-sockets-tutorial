# 🔌 01 — Основы Сокетов: Простой TCP-сокет (Клиент)

В этом вводном уроке мы разбираем устройство сетевого сокета с самых азов на примере ручной отправки HTTP-запроса без сторонних библиотек (без `requests`, `aiohttp`, `httpx`).

---

## ❓ Что такое сокет?

**Сокет (socket)** — это программная «ручка» (абстракция ОС) на конце сетевого соединения.

```text
[ Наша программа ]                               [ Сервер httpbin.org ]
     |                                                    |
  Сокет A ═══════════════ TCP Тоннель ══════════════════ Сокет B
    🔌                                                     🔌
(наш IP : случайный порт)                          (54.208.105.209 : 80)
```

- Ты выбираешь семейство адресов (`IPv4`) и протокол (`TCP` или `UDP`).
- Операционная система реализует выбранный протокол и управляет тоннелем.

---

## 📡 Протоколы: TCP vs UDP

| Параметр | **TCP** (`SOCK_STREAM`) | **UDP** (`SOCK_DGRAM`) |
|---|---|---|
| **Надёжность** | ✅ Гарантирует доставку | ❌ Потери пакетов не отслеживаются |
| **Порядок** | ✅ Пакеты приходят строго по порядку | ❌ Могут прийти вразнобой |
| **Соединение** | ✅ Требует рукопожатия (Handshake) | ❌ Отправка без предварительного соединения |
| **Где используется** | Web (HTTP, WebSocket), SSH, базы данных | Стриминг видео, VoIP, DNS, онлайн-игры |

---

## 🤝 Трёхстороннее рукопожатие TCP (Three-Way Handshake)

Перед тем как отправить хотя бы один байт данных, вызов `connect()` выполняет 3 шага:

```text
Наш сокет                                 httpbin.org:80
   │                                             │
   │ ────────────── 1. SYN ────────────────────► │  "Хочу подключиться"
   │                                             │
   │ ◄─────────── 2. SYN + ACK ───────────────── │  "Принял, подтверждаю"
   │                                             │
   │ ────────────── 3. ACK ────────────────────► │  "Соединение установлено"
   │                                             │
   ▼                                             ▼
══════════════ Готовы передавать данные ══════════════
```

## 📁 Файлы в этой папке

### [`01_simple_socket.py`](./01_simple_socket.py)
Скрипт выполняет полный цикл клиента «вручную»:
1. **`socket.socket(AF_INET, SOCK_STREAM)`** — создание TCP/IPv4 сокета.
2. **`connect((HOST, PORT))`** — автоматический DNS-запрос (`httpbin.org` → IP) и TCP-рукопожатие.
3. **Ручной HTTP-запрос**:
   ```http
   GET /get HTTP/1.1\r\n
   Host: httpbin.org\r\n
   Connection: close\r\n
   \r\n
   ```
4. **`encode("utf-8")`** — превращение текста в байты перед отправкой по проводу.
5. **`sendall(bytes)`** — надёжная отправка полного буфера байтов.
6. **Чтение в цикле `recv(4096)`** — сборка ответа кусками до закрытия соединения (`b""`).
7. **`decode("utf-8")`** — декодирование байтов ответа обратно в читаемый текст.
8. **`close()`** — освобождение системного дескриптора сокета.

## 🧠 Ключевые выводы

1. **Сеть работает только с байтами (`bytes`)**, а не со строками (`str`). Перед отправкой всегда делаем `.encode()`, а после получения — `.decode()`.
2. **`recv(4096)` читает кусками.** Нельзя рассчитывать, что большой ответ придёт за один вызов — поэтому данные собирают в цикле `while True`.
3. **`b""` означает закрытие.** Когда сервер отправляет все данные и закрывает соединение, `recv()` возвращает пустые байты.
4. **Сокет нужно закрывать.** Не закрытый сокет утекает как дескриптор файла в ОС.
