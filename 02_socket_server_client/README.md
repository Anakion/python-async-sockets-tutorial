# 🔌 02 — Сервер и Клиент: Общение между сокетами

В этом разделе мы пишем **обе стороны сетевого взаимодействия** (и сервер, и клиент) и запускаем их диалог.

---

## 🎯 Цель урока

Понять, как сокет-сервер принимает входящие подключения, почему для общения с каждым клиентом создаётся **новый сокет**, и как работают блокирующие вызовы.

Для удобства изучения обе стороны запускаются в **одном файле** с помощью потоков (`threading`), чтобы в одной консоли наглядно видеть весь процесс шаг за шагом.

---

## 🔄 Архитектура и схема работы

```
[ Серверный поток ]                                 [ Клиентский поток ]
 socket(AF_INET, SOCK_STREAM)                        socket(AF_INET, SOCK_STREAM)
 setsockopt(SO_REUSEADDR)                                         │
 bind(('127.0.0.1', 65432))                                       │
 listen() 👂                                                      │
 server_ready.set() 🚩 ─────────── сигнал готовности ──────────► wait() ⏳
 accept() ⏳ (ждёт клиента) ◄────── TCP Handshake ────────── connect(('127.0.0.1', 65432))
      │                                                           │
   (conn, addr)                                           getsockname() -> случайный порт
      │                                                           │
  conn.recv() ⏳ (ждёт)      ◄──── "Привет, сервер!" (27B) ────── sendall()
  message = decode()                                              │
  reply = "Привет, клиент!"                                       │
  conn.sendall()             ───── ответ сервера (69B) ─────────► recv() 📥
  conn.close() 🔒                                                 close() 🔒
  server_sock.close() 🔒
```

---

## 🧠 Ключевые концепции

| Вызов | Роль | Что делает |
|---|---|---|
| `bind((HOST, PORT))` | Сервер | Закрепляет сокет за конкретным IP и портом. Клиент знает, куда звонить. |
| `listen()` | Сервер | Включает режим приёма. ОС сама проводит TCP-рукопожатие и складывает клиентов в очередь (backlog). |
| `accept()` | Сервер | **Блокирующий вызов.** Забирает клиента из очереди и возвращает пару `(conn, addr)`. |
| `conn` vs `server_sock` | Сервер | `server_sock` только слушает порт 🚪. Данные передаются **только** через `conn` 📨! |
| `SO_REUSEADDR` | Сервер | Разрешает перезанять порт сразу, не ожидая таймера `TIME_WAIT` (~60 сек). |
| `threading.Event` | Общее | Флаг синхронизации: защищает от состояния гонки (*race condition*). Клиент не вызовет `connect()` раньше `listen()`. |
| `getsockname()` | Клиент | Возвращает локальный адрес и случайный порт, выданный ОС клиенту. |

## 📁 Файлы в этой папке

### [`02_two_sockets.py`](./02_two_sockets.py)
Полноценный учебный скрипт с подробным построчным разбором каждого шага:
- Создание слушающего сокета и настройка `SO_REUSEADDR`.
- Привязка `bind()` и прослушивание `listen()`.
- Синхронизация потоков через `threading.Event()`.
- Принятие подключения через `accept()`.
- Обмен байтами (`encode`, `sendall`, `recv`, `decode`).
- Сравнение длины строки `len(str)` и байтов `len(bytes)`.
